# Lissurary (구 Library Auto Scheduler) — Spec

> ⚠️ v3 (방향 전환): 기존 Streamlit/Supabase(BaaS)/OR-Tools/OpenAI 기반 전체 스펙을 폐기하고, 검증된 프로토타입(FastAPI + SQLite)의 구현 범위를 그대로 목표로 삼는다. **전체 시간표 생성 + 데스크 시간표 생성 + 엑셀 다운로드까지가 이번 버전의 끝**이며, 그 이전 버전에서 설계했던 확정/배포·주간 요청·수정요청·이의제기·LLM·대시보드·공휴일 API 연동은 전부 9번 "이번 버전에서 하지 않을 것"으로 이동한다.
> ⚠️ v3.1 (`library_work_scheduler_v4_6_final.zip` 반영, 사실상 최종본): 알고리즘 변경 없음. **다중 관리자 계정(CSV 파일 관리), 학생 개별 등록/수정, 명단 CSV 업로드 방식 이원화(merge/sync), 전체 시간표 생성 전 "활성 학생 전원 최종제출+유형지정" 필수 체크, 운영 DB 초기 무시드**가 추가됨. DB는 **Supabase를 순수 PostgreSQL 호스팅으로만 사용**(Auth/RLS 미사용 — `DATABASE_URL`에 Supabase 연결 문자열만 지정하면 됨).
> ⚠️ v3.3 (v4.7 반영): **학생 시간표 입력기간(시작~마감) 관리**가 추가됨 — 관리자가 지정한 기간 밖이거나 수동 잠금 시 학생 로그인·스케줄 수정이 차단된다. 입력기간이 잠긴 상태에서는 관리자가 개별 학생의 시간표를 직접 열람·대리수정할 수 있다(입력기간이 열려있는 동안엔 학생 본인 입력과의 충돌 방지를 위해 대리수정 불가). 모든 수정(학생 본인/관리자)은 `schedule_audits`에 감사 이력으로 남는다.

## 1. 개요
- 도서관 근로장학생의 **희망 스케줄 취합 → 전체 근로표 자동 배정 → 데스크 근로표 자동 배정 → 엑셀 산출**까지를 자동화하는 웹 애플리케이션.
- 근로 대상자 최대 40~50명 기준.

### 용어 정의
- 근로생: 국가근로로 일하는 학생. 이름 + 학번으로 로그인.
- 관리자: 근로표를 관리하는 담당자. `admins.csv` 기반 계정으로 로그인.
- **전체 시간표**: 근로생 전원의 희망 스케줄(1~3순위)을 바탕으로 자동 배정한 근로표. 이 버전에서는 확정/배포 개념 없이 이 표 자체가 최종 산출물이다.
- **데스크 시간표**: 전체 시간표를 기준으로, 대출·반납 안내 데스크 근무만 별도로 배정한 표.
- **학생 입력기간**: 관리자가 지정하는 "학생이 본인 스케줄을 로그인해서 작성·수정할 수 있는 기간(시작~마감)". 미설정 시 상시 허용, 설정 시 그 기간 밖에서는 학생 로그인 자체가 막힌다.
- 1~3순위: 근로생이 근로 가능한 시간대에 매기는 우선순위(1순위가 가장 선호).
- 근로 유형: A형(월 56~80시간, 주 권장 14~20시간) / B형(월 28~40시간, 주 권장 7~10시간). 학생이 직접 선택하거나 명단 업로드 시 필드로 지정.

## 2. 사용자 및 역할

### 근로생
- 인증: 이름 + 학번 일치 여부로 로그인(비밀번호 없음, 세션 쿠키 유지)
- 할 수 있는 것:
    - 근로 유형(A/B) 선택·저장
    - 요일×시간 그리드에서 개인 희망 스케줄 입력(1~3순위/불가능/수업/미선택), 임시저장·최종 제출
    - **단, 관리자가 지정한 학생 입력기간 내에서만** 로그인·조회·수정 가능(3번 "학생 입력기간" 참고)
- 할 수 없는 것: 다른 학생 스케줄 조회/수정, 근로표 생성, 관리자 화면 접근, 입력기간 밖에서의 로그인·수정

### 관리자
- 인증: `data/admins.csv`(운영에서는 Render Secret File)에 등록된 계정 목록(ID/비밀번호/활성여부, 개수 제한 없음). 파일이 없거나 활성 계정이 하나도 없을 때만 환경변수(`ADMIN_ID`/`ADMIN_PASSWORD`, `ADMIN2_ID`/`ADMIN2_PASSWORD`)로 fallback. CSV는 로그인마다 다시 읽으므로 서버 재시작 없이 계정 추가/변경/비활성화가 즉시 반영되고, 이미 로그인 중인 계정을 비활성화하면 다음 요청에서 세션이 즉시 해제됨
- 할 수 있는 것:
    - 근로생 명단 CSV 업로드(merge: 기존 유지하고 추가만 / sync: 전체 동기화, 명단에 없는 기존 학생 비활성화) 또는 40명 더미데이터 생성
    - 학생 개별 등록·수정(이름/학번/근로유형/활성여부, CSV 없이 1명 단위로도 가능)
    - 학생 목록/제출 상태/근로유형 조회 및 수정
    - **학생 입력기간 설정(시작~마감)/즉시 잠금/설정 해제** — 5.2 참고
    - **개별 학생의 시간표 열람은 언제나 가능, 입력기간이 잠긴 상태에서는 직접 대리수정도 가능** — 5.4 참고
    - 전체 시간표 생성(시간당 최소 인원 설정) — 단, 활성 학생 전원이 최종 제출 + 근로유형 지정을 완료해야 실행 가능(4번 "생성 전제조건" 참고)
    - 데스크 시간표 생성(A/B형 주간 최대 데스크시간, 하루 최대시간, 2인 허용 시간대 설정)
    - 결과 엑셀 다운로드
- 할 수 없는 것: 학생 입력기간이 **열려있는 동안** 학생 스케줄 대리수정(충돌 방지 — 409로 차단), 학생 제출 현황 CSV 다운로드(v4.6에서 제거됨)

## 3. 데이터 모델 (실제 구현 기준)

DB는 **Supabase의 PostgreSQL을 순수 DB 호스팅으로만 사용**한다(`DATABASE_URL`에 Supabase 연결 문자열 지정, SQLAlchemy+`psycopg`로 연결). Supabase Auth/RLS/Storage 등 BaaS 기능은 사용하지 않는다 — 인증은 앱 자체 세션 쿠키(2번 참고), 접근 제어는 애플리케이션 코드가 담당한다. 운영 배포 시 DB는 **빈 상태로 시작**하며(자동 시드 없음), 관리자가 화면에서 학생을 등록해야 로그인이 가능해진다.

| 테이블 | 컬럼 | 설명 |
|---|---|---|
| `students` | id, name, student_no(unique), work_type(''/A/B), active | 근로생 명단. CSV 업로드 시 upsert, 명단에서 빠진 기존 학생은 비활성화 |
| `schedules` | id, student_id(FK, unique), schedule_json, state(draft/submitted), saved_at, submitted_at | 학생 1인당 최신 희망 스케줄 1개(JSON: `{요일: {시간: 상태값}}`) |
| `schedule_revisions` | id, student_id(FK), schedule_json, state, created_at | 스케줄 저장 시마다 이력 적재(감사용, append-only) |
| `schedule_runs` | id, full_schedule_json, desk_schedule_json, student_summary_json, summary_json, created_at | 전체/데스크 시간표 생성 결과 스냅샷. 최신 1건을 화면에 표시 |
| `system_settings` | key(PK), value | 범용 key-value 설정 저장소. 현재는 학생 입력기간 시작/마감(UTC ISO 문자열)·수동잠금 여부(3개 key) 저장에만 사용 |
| `schedule_audits` | id, student_id(FK), actor_type(student/admin), actor_id, state, schedule_json, created_at | 스케줄이 **누구에 의해**(학생 본인 vs 관리자, 관리자면 `admin_id`) 변경됐는지 append-only로 기록하는 감사 로그. `schedule_revisions`와 별개로, 매 저장마다 두 테이블에 동시 기록됨 |

- 상태값(schedule 셀): `unselected`(미선택) · `first`(1순위) · `second`(2순위) · `third`(3순위) · `impossible`(불가능) · `class`(수업) · `closed`(운영 안 함, 토요일 비활성 시간대 등 시스템이 강제 지정)
- 근무 가능으로 취급되는 상태: `first`/`second`/`third`

## 4. 근로 규정 (비즈니스 룰)

**영업시간 (고정값, 학기/방학 구분 없음)**
- 평일 09:00~22:00 (`HOURS = 9~21`)
- 토요일 09:00~15:00 (`SATURDAY_ACTIVE_HOURS = 9~14`), 나머지 시간은 `closed`로 고정
- 일요일은 애초에 요일 목록에 없음(운영 안 함)

**스케줄 입력 규칙**
- 1시간 단위
- 같은 요일 내 근무 가능 상태(1~3순위) **연속 최대 4시간** — 초과 시 저장 자체가 거부됨(하드 검증, `validators.validate_schedule`)
- 근로 유형별 1순위 총 시간 권장 범위(A형 주 14~20시간 / B형 주 7~10시간)는 **경고만 표시하고 제출을 막지 않음** — 최종 제출 시에만 경고 계산

**근로 유형 구분 (A형/B형)**
- A형: 월 56~80시간, B형: 월 28~40시간
- 학생이 직접 선택(또는 명단 CSV의 `work_type` 필드로 사전 지정 가능). 최종 제출 전에는 반드시 A 또는 B가 선택되어 있어야 함(미지정 상태로는 제출 불가)

**학생 입력기간 (v4.7 신규)**
- 관리자가 시작 시각·마감 시각(분 단위, 한국시간 기준 입력 → 서버는 UTC로 변환 저장)을 지정하면, 그 기간 **밖**에서는 학생 로그인·조회·저장 API가 전부 423(Locked)으로 차단됨
- 관리자가 "지금 즉시 잠금"을 누르면 시작/마감 설정과 무관하게 즉시 잠김(`manual_lock`)
- 입력기간을 아예 설정하지 않았으면(`configured=false`) 상시 허용 — 기존 v4.6까지의 동작과 동일
- 이미 로그인해 있던 학생도, 기간이 지나거나 관리자가 잠그면 **다음 요청부터** 즉시 차단되고 세션이 초기화됨(`current_student_id`에서 매 요청마다 재검증)

**전체 시간표 생성 전제조건 (v4.6 신규)**
- 활성(active) 학생이 1명 이상 존재해야 함
- 활성 학생 **전원**이 스케줄을 최종 제출(`submitted`) 상태여야 하고, 근로유형(A/B)이 지정되어 있어야 함
- 미충족 시 생성이 거부되며, 미제출자 명단(최대 6명 표시 + 나머지 인원수)과 유형 미지정 인원수를 에러로 안내
- 명단(학생 추가/수정/CSV 업로드)이나 개별 학생의 스케줄이 변경되면(학생 본인이든 관리자 대리수정이든), 그 시점에 저장되어 있던 이전 `schedule_runs`(전체/데스크 시간표 결과)는 자동 폐기됨 — 화면과 다운로드는 항상 최신 명단·제출 기준으로 다시 생성해야 함

## 5. 기능 명세

### 5.1 근로생 — 로그인 / 희망 스케줄 입력
- 입력: 이름, 학번(로그인) / 근로유형 선택 / 요일×시간 그리드 클릭(PC 드래그, 모바일 터치 드래그로 다중 선택)
- 처리: 입력기간이 열려있는지 먼저 확인(닫혀있으면 로그인 화면에 안내 문구 표시 + 로그인 버튼 비활성화, 로그인 시도 시 423) → 로그인 성공 시 세션 저장 → 개인 스케줄 조회/편집 → 임시저장(draft) 또는 최종 제출(submitted). 저장할 때마다 `schedule_revisions` + `schedule_audits`(actor_type=`student`)에 동시 기록
- 출력: 저장 상태, 연속 4시간 초과 시 에러 메시지, 최종 제출 시 권장 시간 범위 경고(있는 경우), 입력기간 잠금 시 안내 메시지
- 제약: 최종 제출은 근로유형이 A 또는 B로 지정되어 있어야 가능. 토요일 비활성 시간대·일요일은 애초에 선택 불가. 입력기간이 닫혀있으면 위 모든 동작 불가(401/423)

### 5.2 관리자 — 학생 입력기간 관리
- 입력: 입력 시작 일시·마감 일시(관리자 화면에서 한국시간 기준 선택), 또는 "지금 즉시 잠금" / "기간 설정 해제" 버튼
- 처리: 시작·마감 저장 시 `system_settings`에 UTC로 변환해 저장하고 수동잠금 플래그는 자동 해제. 즉시 잠금은 수동잠금 플래그만 켬(시작/마감 값은 유지). 설정 해제는 시작/마감/수동잠금을 전부 비움(상시 허용으로 복귀)
- 출력: 현재 상태(열림/잠김), 사유(수동잠금/시작전/종료됨/미설정), 설정된 시작·마감 값
- 제약: 마감은 시작보다 반드시 뒤여야 함(아니면 422)

### 5.3 관리자 — 명단 관리
- 입력: 근로생 명단 CSV(`name,student_no,work_type,active` 4개 열 필수) 업로드(모드: `merge`/`sync` 선택) 또는 "40명 더미데이터 생성" 버튼, 또는 학생 개별 등록/수정 폼(이름/학번/근로유형/활성여부)
- 처리:
    - CSV `merge` 모드: 학번 기준 upsert만 수행, 명단에 없는 기존 학생은 그대로 유지(비활성화하지 않음)
    - CSV `sync` 모드: upsert 후 명단에 없는 기존 학생은 비활성화(전체 동기화). 빈 명단으로는 sync 불가
    - 학번 중복 검증, `work_type`은 빈 값/A/B만 허용
    - 개별 등록/수정: 학번 중복 시 거부, 나머지 검증은 CSV와 동일
    - 더미데이터는 전부 가상 이름(`더미학생01...`)·가상 학번(`DUMMY001...`)으로 생성(실명 미포함), A/B 절반씩 현실적인 패턴(2시간 블록 우선, 균형 배분)의 희망 스케줄까지 자동 생성하고 `submitted` 상태로 저장
    - 명단이 변경되면(개별 등록/수정, CSV 업로드 모두) 기존 `schedule_runs`는 자동 폐기
- 출력: 처리된 학생 수, 학생 목록(이름/학번/유형/활성여부/제출상태/저장·제출 시각), 생성 준비 상태(활성 인원/제출 완료 인원/미제출자/유형 미지정자)
- 제약: CSV는 2MB 이하, `.csv` 확장자만 허용, 열 이름이 4개 모두 일치해야 함

### 5.4 관리자 — 학생별 시간표 열람 및 대리수정
- 입력: 학생 목록에서 "시간표 보기/작성" 클릭 → 팝업으로 해당 학생의 최신 스케줄 표시. 대리수정 시에는 상태 브러시(1~3순위/불가능/수업/미선택) 선택 후 셀 클릭
- 처리: 열람은 입력기간 상태와 무관하게 언제나 가능. **대리수정은 입력기간이 열려있으면 409로 차단**(학생 본인 입력과의 충돌 방지) — 입력기간이 잠긴 상태에서만 저장 가능. 저장 시 연속 4시간 하드 검증은 학생 입력과 동일하게 적용되며, `schedule_audits`에 `actor_type=admin`, `actor_id=관리자ID`로 기록됨. 명단/스케줄 변경이므로 기존 `schedule_runs`도 함께 폐기
- 출력: 조회 시 학생 정보(이름/학번/유형/활성여부)와 최신 저장 시각, 상태 칩(미작성/임시저장/최종제출), 대리수정 완료 시 "수정자: {관리자ID}" 표시
- 제약: 학생이 존재하지 않으면 404. 입력기간이 열려있는 동안 저장 시도는 409

### 5.5 관리자 — 전체 시간표 생성
- 입력: 시간당 최소 인원(`min_staff`, 기본 5)
- 처리: 4번 "생성 전제조건" 충족 여부를 먼저 확인(미충족 시 422 에러로 차단) → 6번 "알고리즘 명세" 참고. 결과를 `schedule_runs`에 스냅샷 저장(요청마다 새 run 생성, 화면은 최신 run만 조회)
- 출력: 요일×시간별 배정 인원 목록, 학생별 목표시간/실배정시간, 스왑 발생 내역, 최소 인원 미충족 칸 경고
- 제약: 활성 학생 수가 `min_staff`보다 적으면 생성 거부. 활성 학생 전원이 최종 제출 + 유형 지정을 완료하지 않으면 생성 거부(4번 참고)

### 5.6 관리자 — 데스크 시간표 생성
- 입력: A형 주간 최대 데스크시간, B형 주간 최대 데스크시간, 하루 최대 데스크시간, 데스크 2인 허용 시간대 목록(그 외 시간대는 3인 필요)
- 처리: 반드시 직전에 생성된 전체 시간표(`schedule_runs` 최신 row의 `full_schedule`)를 입력으로 사용. 없으면 생성 거부
- 출력: 요일×시간별 데스크 배정 인원, 학생별 데스크 배정시간, 2시간/1시간 블록 수, 분할 배정 건수, 미충족 칸 경고
- 제약: 전체 시간표 없이는 생성 불가(기준 총 근로표만으로 생성 — "확정" 개념 자체가 없으므로 항상 최신 전체 시간표 기준)

### 5.7 관리자 — 결과 다운로드
- 엑셀 다운로드: 최신 `schedule_run`을 `전체시간표`/`데스크시간표`/`학생별요약`/`생성정보` 4개 시트로 변환

## 6. 알고리즘 명세

### 6.1 전체 시간표 생성 — 스왑 휴리스틱
> spec v2에서 "1~3지망 처리 방식 3안 중 미결정"으로 남겨두었던 항목의 **최종 결정**: zip 프로토타입에서 검증된 **3안(1순위 전량 배정 후 부족분만 2·3순위와 교환)**을 채택한다.

1. 모든 학생의 **1순위 시간을 그대로 초기 배정**으로 사용한다(이 시점에 학생별 "목표 시간" = 1순위로 제출한 시간 수로 고정됨).
2. 시간당 배정 인원이 `min_staff` 미만인 시간(deficit)을 찾는다. 2·3순위 대체 후보가 적은 deficit부터, 그리고 현재 인원이 적은 deficit부터 우선 처리한다.
3. 각 deficit에 대해, 그 시간에 2순위 또는 3순위를 표시했고 아직 배정되지 않은 학생 중에서 후보를 찾는다.
4. 후보 학생은 **자신의 1순위 배정 중 인원이 `min_staff`보다 여유 있는 칸을 하나 제거**하고, 그 대신 deficit 칸에 배정된다 — 이 스왑으로 학생의 **주간 총 배정 시간은 항상 원래 1순위 시간 수와 동일하게 유지**된다.
5. 스왑 대상 선정 점수: 2순위(가중치 100) > 3순위(가중치 60), 제거 가능한 칸의 여유 인원이 클수록/같은 요일일수록 가산점, 이미 여러 번 스왑된 학생일수록 감점.
6. 후보가 없는 deficit은 경고로 남기고(`"...시간은 2·3순위 교체만으로 최소 N명을 채우지 못했습니다."`), 최대 500라운드까지 반복하거나 더 이상 진전이 없으면 종료.
7. 특정 시간대에 2·3순위 희망자가 아예 없으면 자동으로 채워지지 않으며, 담당자가 결과를 보고 수동으로 조정한다(시스템은 경고만 표시).

### 6.2 데스크 시간표 생성
1. 필요 인원: 관리자가 지정한 "2인 허용 시간대"는 2명, 그 외는 3명.
2. 요일별로 **2시간 연속 블록을 우선** 채운다 — 두 시간 모두 전체 시간표에 배정되어 있고, 주간·일일 한도를 넘지 않는 학생 중 점수가 가장 높은 학생을 반복 배정.
3. 남은 1시간 단위 수요는, 먼저 "하루 1블록 원칙"을 지키는 후보로 채우고, 그래도 부족하면 "하루 2번째 블록 허용"으로 완화해 채운다(이 경우 경고 기록).
4. 학생별 주간 데스크 시간은 근로유형별 상한(A/B 각각 설정값), 하루 배정 시간은 하루 최대값을 넘을 수 없다.
5. 시드를 바꿔 최대 36회 반복 생성 후, **미충족 칸이 가장 적고 2시간 블록이 가장 많은** 결과를 채택한다.

### 6.3 하드 제약 (반드시 지켜야 하는 조건)
- 1시간 단위 배정
- 같은 요일 연속 근무 가능(1~3순위) 시간 최대 4시간 — 학생 스케줄 저장 시점에 검증(관리자 대리수정 시에도 동일 적용)
- 데스크 시간표: 학생별 주간 데스크시간(근로유형별 상한), 하루 최대 데스크시간 초과 불가
- 전체 시간표 스왑 시 학생의 주간 총 배정 시간은 원래 1순위 시간 수를 넘거나 모자라지 않아야 함(불변식)
- 전체 시간표 생성은 활성 학생 **전원**이 최종 제출 + 근로유형 지정을 완료해야만 실행 가능(4번 "생성 전제조건" 참고)
- 학생 로그인·스케줄 조회·저장은 학생 입력기간이 열려있을 때만 가능(4번 "학생 입력기간" 참고)
- 관리자의 학생 시간표 대리수정은 학생 입력기간이 **잠긴 상태에서만** 가능(4번/5.4 참고)

### 6.4 소프트 목표
- 데스크 배정 시 2시간 연속 블록을 1시간 분할 배정보다 우선
- 더미데이터 생성 시 1순위 시간이 특정 시간대에 몰리지 않도록 균형 배분(실서비스 배정 로직 자체에는 균형 배분 소프트 목표가 없음 — follow-up 참고)

## 9. 이번 버전에서 하지 않을 것 (follow-up)
아래는 이전 spec(v2)에서 설계했던 항목들이며, 이번 버전 범위(전체 시간표 + 데스크 시간표 + 엑셀 다운로드 + 학생 입력기간 관리)에서 전부 제외한다. 재도입 시 별도 논의 후 이 문서에 새 섹션으로 추가한다.
- **확정/배포 워크플로우**: "기준"과 "확정" 근로표 구분, 관리자 수동 확정·배포, 배포 여부 관리
- **주간 추가/제외 요청**: 학생의 주간 근무 추가·제외 신청 및 관리자 승인/거절
- **수정요청 / 이의제기(학생 주도 요청 워크플로우)**: 분기 1회 수정요청, 무제한 이의제기, 관리자 검토 화면. ⚠️ v4.7의 "관리자 대리수정"은 이걸 대체하지 않는다 — 대리수정은 어디까지나 **관리자가 임의로** 여는 기능이고, 학생이 사유를 적어 "요청"하고 관리자가 승인/거절하는 정식 워크플로우는 여전히 없음
- **LLM 연동**: OpenAI API 기반 자유서술 완전성 체크, JSON 사전 추출, 자동 반영
- **상태 대시보드**: 근로생/관리자용 실시간 지표 집계
- **공휴일 API 연동**: 공공데이터포털 특일정보 API, 분기별 캐싱
- **학기/방학별 영업시간 차등, 시험기간 연장**: 현재는 고정 영업시간(평일 09~22시, 토요일 09~15시)만 지원
- **base 스케줄 잠금/초기화**: 분기 전환 시점 재입력 잠금 로직(학생 입력기간과는 별개 개념 — 입력기간은 "언제 입력 가능한가"이고, 이건 "분기가 바뀌면 기존 제출을 리셋하는가"에 대한 것으로 아직 없음)
- **Supabase Auth/RLS**: 현재는 Supabase를 순수 Postgres 호스팅으로만 사용. 인증은 세션 쿠키 + `admins.csv` 기반 다중 관리자 계정 / 학생 이름·학번 매칭 로그인
- **OR-Tools 기반 최적화**: 채택하지 않음 — 6.1의 스왑 휴리스틱이 최종 알고리즘
- **학생 제출 현황 CSV 다운로드**: v4.6에서 제거됨. 필요 시 관리자 화면의 학생 목록을 직접 참고
- **관리자 비밀번호 해시화**: `admins.csv`에 평문 비밀번호가 저장됨(운영 배포 전 보안 검토 필요, `docs/architecture.md` 9번 참고)
