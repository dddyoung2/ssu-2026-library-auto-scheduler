# Library Auto Scheduler — Spec

## 1. 개요
- 도서관 근로장학생 근로표 작성 업무를, LLM과 최적화 알고리즘(OR-Tools)으로 자동화하는 스케줄링 시스템

### 용어 정의 (근로생/관리자, 분기/주간, 1~3지망 등 — 코드에서도 이 용어 그대로 씀)
- 근로생: 본 도서관에서 국가근로로 일하게 되는 장학생
- 관리자: 본 도서관에서 직원으로 일하시는 사서 선생님
- 분기 근무표: 시간표 형태가 바뀌는 기준인 분기 단위(학기 - 방학)마다 지속되는 근무표
- 주간 근무표: 분기 근무표의 근무하는 시간대 내, 주간마다 고정되어 따로 대출 반납 안내 데스크에서 일하게 되는 근무표
- 1~3지망: 분기 근무표를 생성하기 전 근로생들별 근로 가능 시간, 불가능 시간 관련 개인 희망 스케줄 입력받을 때 자신이 근로 가능한 시간에 대한 순차 지망
- 근로 유형: A - 월 56~80시간 근로 가능한 유형, B - 월 28~40시간 근로 가능한 유형

## 2. 사용자 및 역할
### 근로생 (권한, 할 수 있는 것)
- 정의: 본 도서관에서 근로하는 국가근로장학생
- 인증: <DB 미설계>
- 데이터 접근 범위: <DB 미설계>
- 할 수 있는 것: 본인 분기/주간 단위별 개인 희망 스케줄 입력, 본인 개인 분기/주간 근로표 확인, 개인 근로 추가·제외 요청(횟수 제한 없음) / 개인 사정 수정 요청(분기별 1회 제한) / 개인 스케줄 미적용 이의 제기(횟수 제한 없음)
- 할 수 없는 것: 다른 사람 스케줄 입력, 다른 사람 분기/주간 근로표 확인, 표 생성 및 데이터베이스 접근

### 관리자 (권한, 할 수 있는 것)
- 정의: 본 도서관에서 근로하는 담당 직원/사서
- 인증: <DB 미설계>
- 데이터 접근 범위: <DB 미설계>
- 할 수 있는 것: 근로지 근로생 총 명단 업로드 및 인적사항 확인, 근로생 각 개인 희망 스케줄 제출 여부 확인 및 스케줄 디테일 확인, 분기/주간 근로표 생성 규칙 수정 및 저장, 분기/주간 근로표 근로생 최소 근무 시간 또는 인원 설정, 분기/주간 근로표 확정 및 배포, 각 표 엑셀로 다운로드, 특별 기간(공휴일, 시험 기간)에 대한 근로 시간 설정, 주간 추가·제외 / 이의 신청 / 수정 요청 승인/거절
- 할 수 없는 것: 근로생 개인 희망 스케줄 임의 조작 및 수정

## 3. 데이터 모델 (아직 설계안함, follow-up)
- students, schedules, work_orders, operating_hours, calendar_exceptions 테이블 정의
- 각 테이블 컬럼, 타입, JSONB 구조 (상태 코드 1~6 포함)
- 관계(FK) 다이어그램 또는 설명
**follow-ups**
- work_orders에 배포 여부(boolean 또는 status) 필드 필요
- 수정 요청/이의 신청 테이블에 상태(pending/approved/rejected) 필드 필요 — 대시보드 카운트와 생성 시 알람 둘 다 이 필드를 씀
- 수정 요청은 상태와 무관하게 '해당 분기 row 존재 여부'만 체크하면 재제출 제한 구현 가능

## 4. 근로 규정 (비즈니스 룰)
**근로지 영업 시간**
- 학기중 평일 09:00~22:00, 토요일 09:00~15:00(시험기간 토요일 09:00~17:00) 
- 방학중 평일 10:00~20:00

**근로표 작성 규칙**
- 근로표 작성은 무조건 1시간 단위로 작성
- 하루 최대 8시간, 최대 연속 4시간까지 근로가 가능하며, 최대 연속 근로 이후에는 1시간 휴식
- 정규 수업 시간에는 근로가 불가능함.
    - 수업이 근로 1시간 칸과 일부라도 겹치면, 해당 칸 전체를 '정규 수업'으로 처리
    - 예: 수업이 15:00~16:15인 경우, 15:00~16:00과 16:00~17:00 두 칸 모두 '정규 수업'으로 선택 (16:00~17:00 근로 불가)

**근로 유형 구분 (A형/B형)**
- **A형:** 월 56~80시간 (주 작성 권장 14~20시간)
- **B형:** 월 28~40시간 (주 작성 권장 7~10시간)
- 근로유형은 학교 근로장학 신청 단계에서 자동 결정되어, 관리자의 "명단 업로드" 시 학생별 속성으로 함께 들어옴 → 시스템은 별도 판정 없이 명단 데이터의 필드로 그대로 저장·활용

**특수 시간대 최소 이수 기준 (A/B형에 따라 다름)**
- 특수 시간대: 평일 09:00~10:00(오픈), 평일 야간 18:00~22:00(마감), 토요일 09:00~15:00(시험기간에는 09:00~17:00, 시험기간은 별도 지정)
- A형은 특수 시간대 주 8시간 이상, B형은 주 4시간 이상 근무를 기본 기준으로 함
- **근로표 생성(OR-Tools) 제약 조건에 반영** — 학생별 근로유형(A/B)에 따라 특수 시간대 최소 이수 시간이 달라지는 제약식으로 추가
- 특정 시간대에 희망자가 없는 경우 담당자가 조정하거나 당번제로 운영할 수 있음

**미선택 시간 처리**
- 학생이 선택하지 않은 시간대는, 해당 시간대 인원이 부족할 경우 배정될 수 있음

**우선순위 배정 원칙**
- 1순위 → 2순위 → 3순위 순으로 우선 배정 *(기존 알고리즘 절차와 일치)*

**시간대 배분 균형 원칙**
- 오전·오후·평일 야간·토요일 시간이 한쪽에 지나치게 몰리지 않도록 배정

**최종 배정**
- 전체 근로시간표 확정 후, 데스크/서가(배가) 업무는 별도로 배정됨
- 토요일·야간 신청 인원이 많으면 담당자가 추후 조정


## 5. 기능 명세
### 5.0 공통 – 상태 대시보드 (모든 화면 상단 고정)
#### 근로생 화면
- 입력: 없음 (로그인만 필요)
- 처리: 로그인 시 본인 데이터 기준으로 4개 지표 실시간 조회
- 출력:
    1. 분기 근무표 배포 여부: Y/N
    2. 주간 근무표 배포 여부: Y/N
    3. 본인 수정 요청 제출 여부: 미제출(0)/제출 완료(1) — 결과(대기·승인·거절)와 무관하게 제출 시점에 1로 고정
    4. 본인 이의 신청 건수: int(승인·거절 결과 확정 시 건수 숫자 감소)
- 제약: 본인 데이터만 집계 (RLS 범위와 동일)

#### 관리자 화면 (지표 5종)
- 입력: 없음
- 처리: 전체 근로생 기준으로 4개 지표 실시간 집계
- 출력:
    1. 분기 근무표 배포 여부: Y/N (현재 분기 전체 배포 상태)
    2. 주간 근무표 배포 여부: Y/N
    3. 처리 대기 중인 주간 추가/제외 요청 건수: int
    4. 처리 대기 중인 수정 요청 건수: int
    5. 처리 대기 중인 이의 신청 건수: int
- 제약: 대기(pending) 상태만 카운트, 승인/거절 완료된 건은 제외

### 근로생
#### 5.1 개인 희망 스케줄 입력(분기/주간 근로표)
- 입력:
    1. (분기) 강의시간, 개인 불가 시간, 1~3지망 근로 희망 시간 — 드롭다운 폼, 1시간 단위
    2. (주간) 추가/제외 구분, 일자, 시간, 사유 — 고정 4개 필드
- 처리:
    1. (분기) 근로일정 설정(operating_hours/calendar_exceptions) 범위 내에서만 선택 가능. 수업시간과 겹치는 칸은 자동 '정규 수업' 처리되어 선택 불가
    2. (주간) 사유 제외 3개 필드는 즉시 저장, 사유는 관리자 승인 대기 상태로 전환
- 출력:
    1. (분기) schedules 테이블에 JSON으로 저장
    2. (주간) 승인 시 주간 데스크 근로표 생성 로직에 반영
- 제약:
    1. (분기) 자유 서술 없음, 1시간 단위만 선택 가능, 근로유형(A/B)별 특수 시간대 최소 이수 시간 화면 안내
    2. (주간) 사유 외 3개 필드는 자유 서술 불가

#### 5.2 개인 분기/주간 근로표 확인
- 입력: 없음 (로그인만 필요)
- 처리: Supabase Auth 로그인 후 RLS 기준 본인 student_id에 해당하는 근로표만 조회
- 출력: 본인 이름 기준 자동 필터링된 분기 근로표 + 주간 데스크 근로표 화면 표시
- 제약: 타 학생 데이터 조회 불가

#### 5.3 개인 이의 사항
- 입력:
    1. (수정 요청) 수정 요청 사유(텍스트), "제출 전 신중히 작성하세요, 결과와 무관하게 분기당 1회만 제출 가능합니다" 경고 문구 출력 후 진행.
    2. (이의 제기) 요청 미반영에 대한 이의 사유
- 처리:
    1. (수정 요청) 배포된 확정 근로표에 대해 분기당 1회 한정 제출, 이미 요청 이력 있으면 버튼 비활성화
    2. (이의 제기) 관리자에게 별도 알림/목록으로 전달
- 출력:
    1. (수정 요청) 요청 상태(대기/승인/거절) 표시
    2. (이의 제기) 처리 상태 표시
- 제약:
    1. (수정 요청) 분기당 제출 1회로 제한 — 승인/거절 결과와 무관하게, 제출하는 순간 횟수가 소진됨. 이미 제출 이력이 있으면(결과 대기/승인/거절 무관) 버튼 비활성화
    2. (이의 제기) 별도 횟수 제한 없음

### 관리자
#### 5.4 근로지 전체 근로생 인적사항 업로드 및 개인 희망 스케줄 관련 확인
- 입력:
    1. (업로드) 근로생 명단 파일(CSV/엑셀) — 학번, 이름, 근로유형(A/B) 등
    2. (제출 확인) 없음 — 목록에서 학생 선택
- 처리:
    1. (업로드) 검증(중복/누락 체크) 후 students 테이블 저장
    2. (제출 확인) 분기/주간 스케줄 제출 여부와 상세 내용 조회
- 출력:
    1. (업로드) 저장 결과
    2. (제출 확인) 제출 여부 목록 + 개별 스케줄 미리보기
- 제약:
    1. (업로드) 근로유형(A/B)은 시스템이 판정하지 않고 업로드 데이터 필드를 그대로 사용
    2. (제출 확인) 해당 없음

#### 5.5 근로생 분기/주간 근로표 생성 및 임시 확인, 시간대별 인원 지정 및 규칙 수정
- 입력:
    1. (중앙_분기 근로표 생성) 학생 제출 데이터 + 저장된 생성 규칙
    2. (아래_데스크 근로표 생성) 확정된 분기 근로표 + 승인된 주간 특이사항
    3. (위_규칙 수정) 최소 근무 인원, 특수 시간대 이수 기준 등 수정값
- 처리:
    1. (중앙_분기) 생성 버튼 클릭 시, 대기 중인 근로 추가/제외 요청, 수정 요청 또는 이의 신청이 1건 이상 있으면 확인 알람 표시: "처리하지 않은 요청이 있습니다. 그대로 생성을 진행하시겠습니까?" [예 / 아니요] → '예' 선택 시에만 OR-Tools 생성 로직 실행, '아니요' 선택 시 5.6 화면으로 이동 유도
    2. (아래_데스크) 동일한 확인 알람 로직 적용 (데스크표 생성 버튼도 동일)
    3. (위_규칙 수정) 변경 없음
- 출력:
    1. (중앙_분기) 생성된 근로표(임시) → 관리자 수동 수정 → 확정/배포
    2. (아래_데스크) 생성된 데스크표 → 수동 수정 → 확정/배포
    3. (위_규칙 수정) 갱신된 규칙이 다음 생성부터 반영
- 제약:
    1. (중앙_분기) 대기 요청이 있어도 강제 차단하지 않음 — 관리자 최종 판단에 맡김 (경고만 표시)
    2. (아래_데스크) 동일

#### 5.6 근로생 요청 통합 검토 화면 (주간 추가/제외 요청 · 확정 근로표 수정 요청 · 이의 제기)
- 입력:
    1. (A. 주간 추가/제외 요청) 목록에서 "주간 요청" 항목 선택 — 일자, 시간, 사유 표시
    2. (B. 확정 근로표 수정 요청) 목록에서 "분기 요청" 항목 선택 — 요청 사유 표시
    3. (C. 이의 제기) 목록에서 "이의 신청" 항목 선택 — 이의 사유, 관련 근로표 항목 표시
- 처리:
    1. (A) 사유 검토 후 승인/거절 처리 → 승인 시 근로표 생성 로직에 반영
    2. (B) 사유 검토 후 승인/거절 처리 → 승인 시 관리자가 해당 근로생의 근로표를 직접 수정할 수 있는 편집 화면으로 연결 (5.5의 "수동 수정" 기능 재사용)
    3. (C) 사유 검토 후 확정 처리 (해결/기각)
- 출력:
    1. (A) 승인 시 근로표 생성 로직 반영, 거절 시 학생에게 상태 표시
    2. (B) 승인 시 "수정 반영 완료" 상태로 전환, 거절 시 학생에게 상태 표시
    3. (C) 처리 상태(해결/기각) 학생에게 표시
    4. 공통: 세 유형 모두 처리 완료(승인/거절/해결/기각) 시 5.0 대시보드의 해당 지표가 자동 감소
- 제약:
    1. (A) 자동 승인 없음, 반드시 관리자 수동 검토
    2. (B) 승인/거절과 무관하게 제출 시점에 이미 카운트 소진 — 거절되어도 재요청 불가
    3. (C) 별도 횟수 제한 없음, 단 동일 건에 대한 재이의는 제한

#### 5.7 근로일정(영업시간/공휴일) 설정
- 입력: 총 근로일, 학기중/방학중 근로일, 공휴일 불러오기 대상 분기(학기/방학) 선택
- 처리: 선택한 분기 범위만 공공데이터포털 특일정보 API 호출 → calendar_exceptions에 캐싱 저장. 수기 추가/수정도 가능
- 출력: 설정값이 학생 입력 폼·근로표 생성 로직에 즉시 반영
- 제약: 분기 단위로만 조회 가능, 전체 기간 일괄 조회 불가

## 6. 알고리즘 명세
### 근로표 생성 절차
1. 근로생 각자 희망 스케줄표 제출 (1시간 단위, 드롭다운 폼, 1~3지망)
2. 관리자가 근로표 생성 실행 (대기 중인 주간요청/수정요청/이의신청이 있으면 경고 알람 후 진행 여부 확인)
3. 제출 데이터를 OR-Tools(또는 채택된 방식)에 입력해 제약 조건 정의
4. 조건을 충족하는 분기 단위 근무명령서 생성
5. 승인된 주간 특이사항(추가/제외)을 반영해 대출반납 데스크 특별 근무명령서 생성

### 하드 제약 (반드시 지켜야 하는 조건)
- 근로표 작성 단위: 1시간
- 하루 최대 8시간, 최대 연속 4시간 + 연속 근무 후 1시간 휴식
- 정규 수업 시간 겹침 칸은 배정 불가
- 특수 시간대(오픈 09~10시/마감 18~22시/토요일 09~15시, 시험기간 09~17시) 최소 이수: A형 주 8시간, B형 주 4시간 이상
- 근로 유형(A/B) 월 시간 범위 준수: A형 56~80시간, B형 28~40시간

### 소프트 목표 (가능하면 지키되, 위반해도 생성은 가능)
- 오전·오후·평일 야간·토요일 시간대가 한쪽에 몰리지 않도록 균형 배분
- 특수 시간대 희망자 부족 시 담당자 조정/당번제 허용

### 1~3지망 처리 방식
⚠️ **팀 결정 대기 — 캐스케이딩 재시도 / 가중치 기반 OR-Tools / zip 검증된 스왑 방식 중 택 1**
(결정 즉시 이 섹션에 구체 로직 채워 넣을 예정)

### 예외 처리
- 조건 충족 실패 시: [선택된 방식에 따른 완화 로직 서술]
- 특정 시간대 희망자 0명: 담당자 수동 조정 또는 당번제
